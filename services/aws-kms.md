# AWS Key Management Service (AWS KMS)

## What the Service Is
AWS KMS is a fully managed service that makes it easy to create and control cryptographic keys used to encrypt and protect data across AWS services and in your applications.

## Description of the Service
AWS KMS uses Hardware Security Modules (HSMs) validated under FIPS 140-2 Cryptographic Module Validation Program to generate and protect keys. It integrates natively with over 100 AWS services (EBS, S3, RDS, DynamoDB, Secrets Manager) and logs all key usage to AWS CloudTrail for regulatory auditing. It uses envelope encryption (encrypting data keys with a root Key Management Key).

## When to Use the Service
- Use AWS KMS to encrypt data at rest across AWS storage and database services.
- Use AWS KMS Customer Managed Keys (CMKs) when you require control over key rotation schedules, key policies, cross-account sharing, and manual key disabling/deletion.

## Key Types and Classes

| Key Type | Key Material Origin | Rotation Capability | When to Use It |
|---|---|---|---|
| **AWS Managed Key** | Created and managed by AWS on your behalf (format: `aws/service-name`). | Rotates automatically every 1 year. | Use when default managed encryption is sufficient; free tier, cannot be deleted or shared across accounts. |
| **Customer Managed Key (CMK)** | Created and managed by the customer within KMS. | Optional automatic annual rotation (or customized 90-365 days); manual rotation via key alias. | Use when you require granular key policies, multi-account sharing, annual auto-rotation, or compliance control over key deletion. |
| **AWS Owned Key** | Internal keys owned and used by AWS to protect data across internal systems. | Managed entirely by AWS. | Use when selecting default encryption on services like S3 (SSE-S3); completely free, not visible in your KMS console. |
| **Imported Key Material (BYOK)** | Key material generated by customer in their on-premises HSM and imported into KMS. | Manual rotation only by creating a new KMS key and updating alias. | Use when compliance mandates that keys must originate from internal corporate on-premises HSMs. |
| **Multi-Region Keys** | Primary key in one region replicated to secondary regions with identical key ID and key material. | Coordinated across regions. | Use for multi-region disaster recovery, active-active architectures, or Aurora Global Databases to avoid cross-region re-encryption. |

## Symmetric vs. Asymmetric Keys

| Dimension | Symmetric Keys | Asymmetric Keys |
|---|---|---|
| **Algorithm** | 256-bit AES-GCM single key for encrypt and decrypt. | RSA (2048, 3072, 4096) or Elliptic Curve (ECC) key pair (public/private). |
| **Performance** | Line-rate hardware acceleration; maximum throughput. | Cryptographically heavier; lower request rate limits. |
| **When to Use** | Default for all standard AWS storage and database encryption. | Use when external parties must encrypt data with a public key without accessing AWS, or for verifying digital signatures outside AWS. |
